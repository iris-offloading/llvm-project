# Reduced reproducer: X86 drops the mask on a dynamic vector-element index

Upstream issue: llvm/llvm-project **218382** — "SIGBUS at `-O2 -mavx2`, terminates
normally at `-O0`", labelled `backend:X86`, `generated by fuzzer`,
`miscompilation`, `needs-reduction`.

## Files

| file       | role                                                     |
|------------|----------------------------------------------------------|
| `repro.c`  | reduced C source, no `stdint.h`, no union macro           |
| `repro.ll` | the same bug as a self-contained `llc` test               |
| `repro.sh` | driver: `./repro.sh [clang] [llc]`                        |

## C source

```c
typedef unsigned v2u32 __attribute__((vector_size(8)));
unsigned long g8, g16;
int main(void) {
  v2u32 v = {0, 3};
  v[0] = __builtin_parity(g16 & 3);
  unsigned long b = __builtin_bit_cast(unsigned long, v);
  g8 = -b;                 /* keep b live as a 64-bit value */
  v[(unsigned char)b] = 0; /* index is 0 */
  g16 = v[0];
  return 0;
}
```

`g16` starts at 0, so `v == {0, 3}`, `b == 0x0000'0003'0000'0000` and the vector
subscript `(unsigned char)b` is **0** — the program is well defined and must exit
0.  It does at `-O0` and with plain SSE2; with SSE4.1 or later it dies on a
signal.

Two corrections to the original report:

* **It is not AVX-specific.** `-msse4.1` is enough; `-mavx`/`-mavx2` behave the
  same.  Only the SSE2-only path is correct.
* **It is a regression.** clang 18 compiles both the original and this reduction
  correctly at every ISA level; clang 24.0.0git does not.  `llc` 18 also gets
  `repro.ll` right, so the regression is in the backend rather than in the IR
  handed to it.

## Backend-only reproducer

```llvm
define <4 x i32> @f(i32 %x) {
  %a = and i32 %x, 1
  %c = call i32 @llvm.ctpop.i32(i32 %a)
  %v = insertelement <4 x i32> splat (i32 1), i32 %c, i64 0
  %b = bitcast <4 x i32> %v to <2 x i64>
  %e = extractelement <2 x i64> %b, i64 0
  %idx = trunc i64 %e to i8
  %r = insertelement <4 x i32> zeroinitializer, i32 0, i8 %idx
  ret <4 x i32> %r
}
```

```
$ llc -mtriple=x86_64-- -mattr=+sse2 repro.ll -o -       # correct
        movq    %xmm1, %rax
        andl    $3, %eax
        movl    $0, -24(%rsp,%rax,4)

$ llc -mtriple=x86_64-- -mattr=+sse4.1 repro.ll -o -     # wrong
        movq    %xmm0, %rax
        movl    $0, -24(%rsp,%rax,4)
```

`%rax` holds `elt0 | (1 << 32)`, so the second form indexes the 16-byte stack
slot at `%rsp - 24 + 0x4'0000'0000`.

## Diagnosis

The DAG going into instruction selection is correct — the index is masked to the
vector length and zero-extended from the low 32 bits:

```
t71: i32 = truncate t38            ; t38 = the i64 from movq %xmm0
t76: i32 = and t71, Constant:i32<3>
t64: i32 = shl t76, Constant:i8<2>
t65: i64 = zero_extend t64
t59: i64 = or disjoint FrameIndex:i64<0>, t65
```

X86 address-mode matching turns the `shl` into the scale and asks for
`zero_extend t76` as the index register.  Selecting that `zero_extend` uses

```
def : Pat<(i64 (zext def32:$src)), (SUBREG_TO_REG (i64 0), GR32:$src, sub_32bit)>;
```

whose `def32` predicate (`X86InstrCompiler.td`) exists precisely to reject
operands whose upper 32 bits are not known zero — `TRUNCATE`,
`EXTRACT_SUBREG`, `CopyFromReg`, `FREEZE`, ….  Here the operand is an `and`, so
`def32` accepts it and no zeroing instruction is emitted.  The `and` is then
selected to *nothing*, because with `elt0 ∈ {0, 1}` the mask `& 3` is redundant,
and `SUBREG_TO_REG` is left sitting on a bare sub-register copy:

```
ISEL: Starting selection on root node: t83: i64 = zero_extend t76
  Morphed node: t83: i64 = SUBREG_TO_REG t76, TargetConstant:i32<6>
ISEL: Starting selection on root node: t76: i32 = and t71, Constant:i32<3>
                                            (no machine node emitted)
ISEL: Starting selection on root node: t71: i32 = truncate t38
  Morphed node: t71: i32 = EXTRACT_SUBREG t38, TargetConstant:i32<6>
```

MIR after `finalize-isel`, bad vs good (the good one is the same test with the
`ctpop` removed, where `def32` sees the `TRUNCATE` and rejects it):

```
  bad                                        good
  %7:gr32 = COPY %5.sub_32bit                %6:gr32 = COPY %4.sub_32bit
                                             %7:gr32 = MOV32rr killed %6
  %8:gr64_nosp = SUBREG_TO_REG killed %7,    %8:gr64_nosp = SUBREG_TO_REG killed %7,
                 %subreg.sub_32bit                          %subreg.sub_32bit
  MOV32mi %stack.0, 4, killed %8, 0, ...     MOV32mi %stack.0, 4, killed %8, 0, ...
```

`SUBREG_TO_REG` asserts that the high half of the destination is zero, so the
coalescer is entitled to replace `%8` with the full 64-bit `%5` — which is how
`movq %xmm0, %rax` ends up being used directly as a scaled index.

The `ctpop` is load-bearing in the reduction, and only through its effect on
known bits: it is what leaves an `and` in the DAG that is *provably redundant at
selection time*.  Without it the mask is already folded away before selection,
`def32` sees the `TRUNCATE`, and the safe `MOV32rr` + `SUBREG_TO_REG` sequence is
emitted.  Correspondingly, making the mask non-redundant (an unconstrained
`elt0`) also produces correct code, with a real `andl $3`.
